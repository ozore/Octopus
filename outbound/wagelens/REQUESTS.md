# WageLens outbound: requests to the engine owner

Logged by the Outbound Copywriter (wave 3, 2026-09-04). Nothing under `outbound/engine/` was
edited; each entry says how the copy works around the gap today. Ordered by how much each one
would change what the founder sees.

| # | Request | Why | Workaround in place |
|---|---|---|---|
| R1 | **Block a draft whose body carries the from-name placeholder.** `check_draft()` tests `postal_address`, `unsubscribe_url` and `from_address` with `is_placeholder()` but not `from_name`, and never scans the body for a placeholder token. Every sequence now signs off with `{{sender.name}}, {{app}}, a {{company}} company`, so an unset `OUTBOUND_FROM_NAME` renders `[SENDER NAME PLACEHOLDER - set OUTBOUND_FROM_NAME]` inside the body and can be approved. | A visible placeholder in a sent email. | `PLAYBOOK.md` section 11 makes `grep -l PLACEHOLDER drafts/<date>/*.json` a pre-flight step, and the morning routine reports it. |
| R2 | **Fact-based routing in `sequence_for()`.** The brief defines `godfather-federal` as "rows with `fact.federal_awards` or `fact.payroll_filings`", but `sequence_map` matches substrings of `segment` only. | Today `godfather-federal` receives 2 rows by segment; 1,414 rows carry `fact.federal_awards` and reach it only through the trade and GC families. | Every segment is mapped explicitly (24 needles). A rule such as `"fact:federal_awards": "godfather-federal"` evaluated after the segment map would let the founder collapse the families without editing 24 lines. |
| R3 | **`personalise._trades()` mis-parses award numbers.** For 42 GC rows `notes` holds award identifiers such as `123456 - 004 (2025-04-17)`; the six-digits-then-dash pattern reads them as NAICS labels and `fact.trades` renders as `004 (2025-04-17) work`. | Any template using `{{fact.trades}}` would print an award number as a trade. | No WageLens sequence uses `fact.trades` (the old `plain-intro` step 3 did; removed). Fix: require the label to start with a letter, and add a test with an award-number note. |
| R4 | **Article before an initialism in `opening_sentence()`.** `_article("MWBE/SBE certified construction firm")` gives "a MWBE/SBE ..." (1 row today, `2goforward-llc-1e7e61`). | Reads as a typo in the first line. | None; one row. Fix: treat a leading capital initialism whose first letter is F, H, L, M, N, R, S or X as vowel-sounding. |
| R5 | **The footer repeats the signature.** `FOOTER_TEXT` prints `{signature}` ("WageLens, a TheVillage company") directly under a body that already ends "Jane Doe, WageLens, a TheVillage company". | Two company lines four lines apart. | Accepted for now. Option: a `sign_off: false` front-matter key that drops `{signature}` from the footer, or print only `{company} - {postal_address}` there. |
| R6 | **A `county` fact.** `OFFER.md` section 9 writes the Godfather subject as "the Davis-Bacon rate for {{county}}"; the workbook has `city` and `state` only, and Davis-Bacon determinations are keyed by county. | The subject and opening say "your county in Arizona" instead of naming it. | Copy asks the recipient for the county (it is the ask). A gazetteer pass in the enrichment scripts (city, state to county) plus a `phrases()` template and a test would let the subject name it. |
| R7 | **A word-count warning in `check_draft()`.** Nothing stops a later edit from turning a 160-word email into a 300-word one. | The brief's limits (170/110/110/70) are enforced only by the scratchpad check. | `PLAYBOOK.md` section 11 lists the check command; the limits are recorded in `CLAUDE.md`. |
| R8 | **A `not_now` outcome.** `reply --kind replied` is terminal; a "try us in March" cannot be re-planned by the engine. | The founder re-contacts by hand, outside the log. | `PLAYBOOK.md` section 5 records it as `replied` with a dated note and a calendar reminder. A `snoozed` stage with `next_action_at` set by `--until` would keep it in the log. |
| R9 | **Auto-reply detection in the evening routine.** The routine prompt in `outbound/README.md` section 3 classifies "a human answered" but does not tell the agent to skip out-of-office and auto-submitted messages. | An out-of-office recorded as `replied` silently ends a sequence. | `PLAYBOOK.md` section 5: an out-of-office is never recorded; the sequence continues. Add "ignore messages with `Auto-Submitted` headers or out-of-office subjects" to the routine prompt (that file is the engine owner's). |
| R10 | **Product-name variable.** Copy uses `{{app}}` (from `display_name`) everywhere the product is named, so the P11 rename is one line in `config.json`. Not a change request; recorded so nobody hard-codes "WageLens" back into a sequence. The support templates under `support/` do hard-code it, because they are pasted by hand, and need a find-and-replace on rename. | | |
| R11 | **`report` overwrites hand-written sections of `REPORT.md`.** `report.report()` calls `path.write_text()` on the whole file, so the wave-3 section appended there disappears on the next run. | The founder's decision list lives in a file the daily routine rewrites. | The durable copy is `CLAUDE.md` section 6. Fix: keep everything below a `<!-- manual -->` marker, or write generated content to `REPORT.md` and hand-written notes to a sibling file. |
